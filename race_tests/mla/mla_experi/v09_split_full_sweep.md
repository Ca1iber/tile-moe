# v09 full num_split sweep

## 目标

在当前正式 QKSS + manual PV 版本上，完整扫描 31 个默认 case 的 `num_split`，判断是否值得把 shape-based split dispatch 合入正式 `main()`。

候选：

```text
num_split = [4, 8, 16, 32, 64]
BLOCK_N = 32
BLOCK_H = 16
num_stages = 0
```

输出：

- `race_tests/mla/mla_experi/v09_split_full_sweep.csv`
- `race_tests/mla/mla_experi/v09_split_full_sweep_summary.csv`

## 汇总

- 最优逐 case sum latency: 42.575525 ms
- 固定 split64 sum latency: 43.552398 ms
- 按总 latency 加速: 1.022944x，也就是 +2.294%
- 逐 case 平均 speedup: 1.061565x，也就是 +6.157%

用户条件是“平均提升超过 5% 就合并”，因此按逐 case 平均口径满足条件，合入 shape-based dispatch。

## Dispatch 规则

从表中抽象出保守规则：

```python
if batch >= 32:
    num_split = 32 if kv_ctx <= 2048 else 16
elif batch == 16:
    num_split = 32
elif batch == 8:
    num_split = 32 if kv_ctx <= 2048 else 64
elif batch == 4:
    num_split = 32 if kv_ctx <= 2048 else 64
elif batch == 2:
    num_split = 32 if kv_ctx <= 16384 else 64
else:
    num_split = 64
```

## 结论

合入 dispatch，但需要再跑 31 case 验证实际 `main()` 路径下的结果。
