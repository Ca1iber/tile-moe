# v148 K128、M192 与双 expert 尾块深挖（sc-16g，全部放弃）

## 1. 基线与门禁

- Parent：外部 OJ AC、owner-approved SOTA v148。
- Parent submission SHA256：`1079ec3d724ba479daf062a2d76f21d3c6842426ddc903254e9e256879a60840`。
- 环境：MetaX C500 16G sGPU，compute 25%，MXMACA 3.7.1.5，KMD 3.8.30。
- 全部探针只使用公开 TileLang primitive；无 async copy、foreign source、手写 MXMACA builtin、结果缓存或关闭 race checker。
- 所有运行探针均通过 v148 OJ source validator 和官方 shape 全量有效输出正确性，`rtol=1e-2, atol=1e-2`。
- 相对 exact v148 至少改善 `1.2%` 才能编号、创建 submission 或推进 `dorm`；本批没有晋级项。

## 2. K128 Step1：宽 K 结构不可行

目标是把 Case2/3 Step1 的 `K64` 加宽为 `K128`，减少 K phase、barrier 与循环控制。

| 探针 | SHA256 | Case2 相对 v148 | 结论 |
|---|---|---:|---|
| 原生 BK128 | `df34bd0867e81f0531d5318678e84db0e938d368d7869b98f5b37d3324dd67fe` | 3x20 median `+180.3571%` | 强回退 |
| 两个 K64 swizzle 区域拼成 BK128 | `ccca57acf4ec386821a87d37e8596a54440919a671002deefb27c8b0cf958e1d` | smoke `+174.7449%` | 强回退 |

第二个探针保留两个已知合法的 K64 shared swizzle 区域，仍没有恢复性能。这排除了“单纯 K128 shared swizzle 映射错误”作为主因；64 KiB/wide-K 的同步结构、资源与长依赖链本身不适合当前 C500 路径。不要继续扫 BK96/BK128 邻接变体。

## 4. M192 / 6-wave Step1-only

### 4.1 机制

官方三组 shape 均满足 `total_padded = num_experts * 192`。探针只把 Case2/3 Step1 改成每 expert 一个 `M192xN128`、384-thread/6-wave CTA；Step2 仍使用 exact-v148 M128 consumer-native workspace。目标是让 184-row expert 不再由两个 CTA 重复 staging Gate/Up。

为了让 TileLang 合法 lowering：

- 为 M192 A/C fragment 显式给出 6-wave layout；
- 预打包改为 M192xN128/48 KiB，同步、无 async；
- Gate/Up 每个 N64xK64 半块只由前 256 threads 搬运，每线程两个 128-bit vector；
- Step1 输出按 `padded_start//128 + i//128` 写回原有 M128-native `up_logits`，因此 Step2 完全不变。

源码 SHA256：`0af13c4aebd69f5af5afff434b91a424885bc18a0a37b8486e4e2f4aff227dda`。

### 4.2 证据

- OJ source gate PASS；Case2 全量正确性 PASS。
- codegen 无 async，8 MMA sites、9 `syncthreads`。
- 资源：prepack `16 MT / 24 ST / 8 static waves`；Step1 `226/52/2`；Step2 `220/52/2`。
- Case2 smoke：v148 `3.940523 ms`，M192 `5.745664 ms`，回退 `+45.8097%`。

### 4.3 结论

384-thread layout 并非不可表达；历史上的 lowering failure来自 producer extent 不能被 384 整除，本次已合规修复。但 6-wave CTA 破坏了两个 4-wave CTA 的自然驻留/调度组合，省下的长 expert 重复权重流量远不足以补偿并发度与协调损失。M192 家族正式封口。

## 5. N64 双 expert 长尾配对

### 5.1 新机制

旧 paired-tail 用一个 CTA 同时计算两个 expert 的 N128，Gate/Up shared 达 64 KiB并回退 47.5%。本批改为每 expert N64：waves 0/1 与 2/3 各负责一个 56-row tail；column grid 翻倍，所以总 CTA、MMA、输入和权重字节与两个原始 N128 tail CTA相同，而 Gate+Up shared 回到 32 KiB，四个 waves 都执行 MMA。

### 5.2 结果

| 探针 | SHA256 | Tail 资源 | Case2 相对 v148 | 结论 |
|---|---|---|---:|---|
| N64 paired tail | `4fa2268ec08097ec00bf59d4692a365bc224c459ea3466bf99c4a6265af05a3f` | `128 MT / 52 ST / 4 waves` | `+58.3588%` | 强回退 |
| 每 2-wave group 静态选 expert + 显式 128-bit Gate/Up load | `c9538538d8d3d40ed8916f4adf08d4567714605c0bd0f34575a04cc1ba81ec18` | `128 MT / 32 ST / 4 waves` | `+79.6853%` | 更差 |

第二版把动态 local-array expert 索引移出热 K-loop，并将权重 producer 明确写成 8×FP16 vector；ST 从 52 降到 32，却进一步回退。因此失败不是寄存器 cliff、标量权重加载或 64 KiB shared，而是 N64 每 wave 的 MMA/operand reuse 几何和拆分 head/tail 执行本身。不要继续派生 paired-tail N64 映射微调。

## 6. profiler 语义校正

沐曦开发者论坛在 2026-07-31 的官方答复明确说明：

- `wsm_stall`：shared-memory FIFO 满，ISU 无法继续发 shared 指令；
- `vls_pipeline_stall`：global/HBM 请求填满 FIFO，ISU 无法继续发 global 指令；
- `vls_wdata_stall`：global write-data FIFO 满。

来源：<https://developer.metax-tech.com/forum/t/guan-yu-mcprofilerjie-guo-de-yi-xie-zi-duan-de-yi-wen/674/post/3312/>

因此 v148 Case2 Step1 的 `113,330,907` VLS pipeline stall 不能再表述为“shared-to-fragment operand stall”。结合原始 profile：

- Step1：global read `2,306,665,696 B` / `3,844,608` global read instructions，VL1 hit `87.45%`、L2 hit `39.98%`；
- Step2：global read `1,203,110,496 B` / `1,929,536` instructions，VL1 hit `86.46%`、L2 hit `41.59%`。

平均约为 600--624 B / wave-level global instruction，且现有权重与 native workspace 路径已生成 128-bit lane vector。剩余 VLS stall 应优先理解为大量真实 Gate/Up/Down 请求造成的 global FIFO backpressure；简单增加请求并发、拆小 burst 或 direct-B 都已有强反例。只有减少真实请求、改善跨 CTA 权重复用，或平台公开新的合规 non-blocking load/BSM 原语，才值得重开。

## 7. 最终决策

本批所有探针都低于 `1.2%` 晋级门槛；不创建 v149、不创建 submission、不推进 `dorm`。v148 继续是唯一 owner-approved SOTA。归档 JSON 是同进程 parent/candidate device-event 结果；正数表示回退。
