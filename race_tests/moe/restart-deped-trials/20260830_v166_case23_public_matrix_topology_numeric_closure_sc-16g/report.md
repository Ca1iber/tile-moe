## Public matrix-load / BSM legality audit

The current inline emitter was compared against TileLang's public `TensorCoreIntrinEmitter` and the installed MACA headers.

1. `TensorCoreIntrinEmitter.ldmatrix_a/b` is a vectorized shared-buffer read into a local fragment and lowers to the same synchronous `lds_b128` family already generated by v166.
2. `T.tvm_mfma` is the public, compliant register-operand matrix primitive used by v166.
3. `T.tvm_load_matrix_sync` maps to `mxmaca::wmma::load_matrix_sync`; the installed FP16 16x16 implementation is ordinary 8-byte/scalar loading, not a synchronous BSM-to-register matrix-load primitive.
4. WMMA `8x32x16` and `32x8x16` are expanded by the SDK into two native `16x16x16f16` builtins plus lane selection. They do not expose a lower native shape and increase temporary state.
5. No public synchronous BSM-to-register or direct-BSM-to-MFMA primitive was found. The only relevant public nonblocking global-to-BSM path is async copy, which is prohibited for this submission.

Therefore replacing the inline emitter with the public helper or WMMA spelling cannot remove the current `lds_b128` operand feed.

## 2x2 topology causal result

The 2x2 fragment layout is legal: TileLang's `Fragment.replicate()` expresses the A duplication, and the consumer-native short input was expanded from four to eight 128-bit slots per thread so every duplicated fragment element has an explicit producer. The candidate compiled and was numerically correct.

However, Case2 moved from `3.450509 ms` to `3.874906 ms`. The theoretical reduction from four B copies to two is outweighed by:

- doubling short-input prepack writes and fragment reads;
- doubling the A fragment state per thread;
- enlarging each wave's output tile from M32xN128 to M64xN64, which keeps the accumulator area but lengthens its dependency lifetime;
- touching only the short-expert third of Step1 CTAs while leaving the dominant long path unchanged.

This closes the intermediate 2x2 Step1 topology; the old 1x4 and current 4x1 endpoints no longer leave an untested uniform four-wave split.

## Numeric boundary

The archived degree-7 form is OJ-tolerance safe on the official Case2 output but saves only `0.2847%`, confirming that one FP32 Horner stage is not an endpoint-critical mechanism. A degree-5 form previously showed roughly `2.8%` timing potential, but its eight-distribution stress suite produced OJ mismatches, with maximum absolute error up to `0.1914`; it is not submission-safe. The piecewise degree-5 form passed that OJ stress suite but regressed about `0.56%` because coefficient selection / divergent tail handling costs more than the removed arithmetic. The numeric family therefore remains closed.

## Final routing

1. Exact v166 remains the only external-OJ SOTA and must remain the `restart-submission` / `dorm` head.
2. Do not retry public-emitter renaming, WMMA alternate shapes, short 2x2/1x4 topology, short Gate/Up pair-load, or single-segment degree-7 SiLU without a genuinely new hardware/compiler condition.
3. Do not promote or stack the `0.17-0.28%` signals; they are below the user-required 1.2% floor.
4. A future restart needs either a new legal nonblocking operand primitive, a way to reduce compulsory Gate/Up/Down traffic without losing CTA parallelism, or a robust low-cost approximation with a new formal error bound.
